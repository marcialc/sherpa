# Repository tools

`RepositorySession` provides the validated `RepositoryTools` interface. The Worker imports the `ReviewSandbox` and `ContainerProxy` Durable Object exports separately from `src/cloudflare.ts`; pure Node tests do not load `cloudflare:workers`.

```ts
const sandbox = getSandbox(env.REVIEW_SANDBOX, `${job.reviewId}-${crypto.randomUUID()}`);
const repository = new RepositorySession(sandbox, {
  validation: trustedBaseConfig.validation,
  allowValidation: env.ALLOW_REPOSITORY_VALIDATION === "true",
});
try {
  const { incrementalBaseSha, warnings } = await repository.prepare(job, previousReviewedSha);
  const files = await repository.getChangedFiles();
  const result = await repository.execute({ tool: "readFile", path: "src/index.ts" });
} finally {
  await repository.destroy();
}
```

Use a fresh Sandbox ID for every attempt. A Sandbox binds exactly one validated job and cannot reopen Git authorization after preparation. Destroy the container in the calling Workflow's `finally` block, including failed preparation. The client adapter methods are `exec`, `destroy`, `beginPreparation`, `endPreparation`, and `setPackageAccess`.

Preparation fetches `refs/pull/<number>/head` from the base repository, which supports fork pull requests without trusting a head repository URL. It verifies the immutable expected HEAD SHA and computes a merge base against the trusted base SHA. A previous reviewed SHA becomes the incremental baseline only when it is available and an ancestor of the new HEAD. History fetches are limited to an initial depth of 256 and one deepening of 1,024 commits; unresolved ancestry fails or falls back explicitly.

Tools use fixed argv arrays through a fixed Python supervisor. Model strings are JSON stdin data, never executable shell interpolation. Paths are validated repository paths and Git literal pathspecs. Revisions are the trusted job SHAs or verified baseline. File reads and searches use immutable Git objects; file reads reject symlinks and submodules. The supervisor bounds combined stdout/stderr while reading pipes, kills process groups on output overflow or timeout, and applies file, descriptor, and process limits. The SDK timeout is a secondary transport ceiling: its own timeout does not kill container processes.

The default tool output cap is 32 KiB, normal command deadline is 20 seconds, and optional validation deadline is 60 seconds, all capped by service code. `readFile` returns up to 500 numbered lines with a 256 KiB source read ceiling. `gitShow` accepts the same optional `startLine`/`endLine` bounds and returns numbered ranges; without either bound it preserves raw source output. Intentional range selection does not mark complete ranges truncated. Ranges beyond the source ceiling or output limit remain explicitly incomplete. `gitShow` attests missing files with successful immutable tree membership inspection, `fileExists: false`, and `FILE_ABSENT_AT_REVISION`; symlinks and other command failures remain failures. `getChangedFiles` accepts at most 200 files, 64 KiB per patch, and 512 KiB total patch content; excess fails closed so the caller must report incomplete review coverage. Rename detection is disabled and renamed files appear as deletion/addition. `findReferences` is a literal textual reference search, not a language server.

GitHub credentials stay in the Workers runtime. The trusted DO installs an outbound policy containing only job identity, phase and expiry. The handler obtains an installation token scoped to that exact repository, permits only Git read protocol paths on `github.com`, strips incoming credentials, and injects Git authorization outside the container. Redirects and Git write endpoints are denied. Every preparation exit closes Git access. All other outbound HTTP(S) is denied except opt-in dependency installation GET/HEAD requests to `registry.npmjs.org` or `registry.yarnpkg.com`; that access closes before project scripts run. No credentials are placed in commands, environment variables, URLs, or repository files.

Validation requires both the service flag and trusted base configuration. Project package scripts additionally require exactly one pnpm/npm/yarn lockfile and a regular `package.json`. Image-pinned pnpm 9 and Yarn Classic 1 avoid executing a project-selected package-manager binary. Installation disables lifecycle scripts and pnpm hooks. Project commands are the named `test`, `typecheck`, `lint`, and `security` scripts, never model-provided commands; each runs once per session. A missing script or lockfile produces a skipped result. Yarn Berry and non-JavaScript dependency setups require a future reviewed adapter.

Project scripts run as UID/GID 65534 with no-new-privileges, a read-only root/Git store, writable working tree, isolated process namespace, and no network via Bubblewrap. The container runtime must support unprivileged user namespaces; otherwise validation fails closed. This nested isolation has not been verified on a live Cloudflare deployment. Dependency downloads use the registry phase without project lifecycle scripts; enabling this feature deliberately gives the package manager access to those public registries. Network policy is a host/request restriction, not a promise against every covert channel (including platform DNS).

`runStaticScan` accepts `scanner: "semgrep" | "opengrep" | "osv"` and requires the service flag plus trusted `validation.enabled` and `validation.security`. Semgrep 1.177.0 is installed in an image-owned virtual environment. Four service-owned rules check dynamic JavaScript evaluation, disabled TLS certificate verification, Python shell execution, and pickle deserialization. This is a narrow evidence collection ruleset, not comprehensive security coverage. Only changed regular JS/TS/Python blobs are copied from immutable Git into a disposable snapshot. HEAD rules, ignore files, package configuration, and suppression comments do not control the scan. Semgrep runs offline with one job, a two-second per-rule/file limit, a 512 MiB engine limit, and the session's bounded output/deadline. OpenGrep explicitly skips because it is not installed. Each scanner has one attempt per review session.

OSV supports npm package-lock v2/v3 only. The Worker reads immutable lockfile content, extracts at most 500 unique exact npm name/version coordinates, and sends one unauthenticated POST to the fixed OSV querybatch endpoint. No lockfile URL, credentials, repository source, or model-selected address is sent. Custom package sources and nonexact versions are excluded and mark coverage incomplete. Responses are streamed with a 256 KiB cap and eight-second deadline; pagination also marks evidence incomplete. Results contain advisory IDs only: they establish a package/advisory match, not reachability, exploitability, or verified CVE impact. No automatic finding should be published from these matches. Yarn/pnpm lockfiles explicitly skip until reviewed parsers are added. This transport does not open Sandbox egress.

`runReproduction` accepts `language: "javascript" | "python"`, a named `hypothesis` of at most 300 characters, and `source` of at most 12,000 characters. It requires the service flag plus trusted `validation.enabled` and `validation.tests`, permits three attempts, and has a maximum 15-second deadline. A fixed runner stages a fresh snapshot from immutable Git objects (at most 1,000 regular files, 256 KiB per file, 16 MiB total) and creates a temporary test file there. Symlinks/submodules are omitted and reported. Snapshot limits fail closed. Installed dependencies and untracked files are not copied. The snapshot is mounted read-only; the original checkout and Git database are hidden. JavaScript CommonJS imports resolve relative to the snapshot, and Python imports include its root. All test writes belong in disposable `/tmp` (64 MiB). The image pins checksum-verified Bubblewrap 0.12.0 because the base distribution version lacks bounded tmpfs support. New user/network/PID namespaces, no-new-privileges, disabled nested user namespaces, a 32-process limit, per-process CPU/address-space/file limits, and the supervisor's output/deadline limits apply. JavaScript additionally runs without JIT and with a 128 MiB V8 heap limit. The Cloudflare container's configured memory limit remains the aggregate outer bound.

A successful reproduction means execution completed with exit 0, not that its hypothesis is true. Programs should catch expected exceptions and report actual versus expected observations, returning exit 0 after collecting them. Unexpected exits, isolation startup failures, output overflow, and timeouts are failed evidence. Scans, reproductions, typechecks, lint, and package tests supply evidence only; the review pipeline still must verify causality, baseline changes, scope, and relevance before producing a finding. No test is committed or pushed to the user's PR.

Local tests execute real Git snapshots and the Python supervisor, including traversal, symlinks, shell-looking file names, immutable reads, incremental baselines, force pushes, stale heads, output floods, silent timeouts, and credential injection policy. They do not prove Cloudflare container startup, HTTPS interception, private Git authentication, or nested Linux namespaces; those require the documented live acceptance run.

Optional local image acceptance: build `docker build --platform linux/amd64 -t sherpa-sandbox:scanner apps/worker`, then run `SHERPA_TEST_DOCKER_IMAGE=sherpa-sandbox:scanner pnpm test packages/sandbox/src/evidence.docker.test.ts`. The suite executes the shipped Semgrep binary/rules on a trusted fixture and checks the complete scanner/reproduction path. On runtimes without user namespace support, those paths must refuse execution and must not produce reproduction observations. Successful refusal does not establish successful nested execution. `SHERPA_TEST_USERNS=1` is an explicit local test-only Docker seccomp setting; it never changes the application's fail-closed behavior.

Local results on 2026-09-14: the image built successfully and Semgrep detected the unsafe-deserialization fixture. All four image acceptance tests passed; this Docker runtime refused user namespace creation, so full scanner and reproduction paths exercised refusal rather than successful nested execution. A separate fixed arithmetic program verified that Node starts under the 1 GiB address-space cap with the configured V8 flags. Live Cloudflare namespace acceptance remains unverified.
